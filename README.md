# DormCalc

DormCalc is a Flask web application for splitting dorm utility costs across multiple residents. Administrators can adjust expenses, track time away, apply credits ("abono"), manage uploaded receipts, and invite renters into their shared workspace. A super admin layer lets you oversee several dorm workspaces on a single deployment.

## Features
- Multi-tenant billing workspaces with admin and renter roles.
- Automatic pro-rating of water, electric, internet, and rent charges based on days present.
- Resident-level abatements for general and mineral "abono" credits.
- Time away tracking with validation against the active billing period.
- Fixed-charge management per utility category in addition to variable usage.
- Receipt uploads (images and PDF) stored per tenant with secure filenames.
- Super admin dashboard to view and prune tenants, admins, and renter accounts.

## Requirements
- Python 3.11+
- pip

Only one Python dependency is required: see `requirements.txt`.

## Getting Started

```bash
python -m venv .venv
source .venv/bin/activate  # On Windows use: .venv\Scripts\activate
pip install -r requirements.txt
python app.py
```

The server defaults to `http://127.0.0.1:5000`. Flask's debug mode is enabled in `app.py` for local development; disable it before production use.

On first launch DormCalc seeds a sample tenant with two residents (John and Mary) and writes persistent data to `data/storage.json`. Each tenant also gets a matching uploads directory under `uploads/tenant_<id>/`.

## Accounts and Roles
- **Admin**: Created through the web UI, owns a single tenant workspace. Admins can rename the dorm, invite renters, manage residents, adjust expenses, credits, and fixed charges, and review uploads.
- **Renter**: Invited via token generated by the admin. Renters can log in to see the live breakdown for their dorm, upload receipts, and update their own out-of-dorm dates or credits (within allowed rules).
- **Super admin**: Out-of-band account for centrally managing every tenant on the server (viewing activity, rotating invite tokens, deleting tenants or accounts). Super admins do not belong to a specific tenant.

### Creating a Super Admin
Use the command-line helper built into `app.py`:

```bash
python app.py superadmin --set my-admin --password "S3cretPass"
```

Omit `--set` or `--password` to be prompted securely. To remove all existing super admin credentials run:

```bash
python app.py superadmin --clear
```

### Resetting Local Data
To wipe local state, stop the app and delete `data/storage.json` along with any `uploads/tenant_*` directories. They will be recreated when the server starts again.

## Project Layout
- `app.py` – Flask application, REST API, calculation logic, and CLI helpers.
- `templates/index.html` – Single-page UI rendered by Flask.
- `static/app.js` – Front-end logic that drives authentication flows, state refresh, and UI interactions.
- `static/style.css` – Styling for the web UI.
- `uploads/` – Per-tenant receipt storage (auto-created).
- `data/` – JSON persistence for tenants, accounts, and billing state (auto-created).

## Development Notes
- The API enforces role-based access through decorators such as `@require_auth`.
- Billing periods default to the 15th–14th cycle; admins can override via the Admin tab.
- File uploads are limited to 10 MB and accept `png`, `jpg`, `jpeg`, `gif`, `webp`, and `pdf` extensions.
- Persisted state is flushed to disk whenever significant changes occur, guarded by a thread lock.

For production deployments consider externalising the secret key, running behind a WSGI server (e.g., Gunicorn), and placing uploads on durable storage.
